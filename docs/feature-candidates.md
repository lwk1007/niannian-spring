# 念念 · 候选功能清单（开源项目 + 网站调研版）

> 调研日期：2026-11-15
> 目的：针对「现状偏单薄」，从同类开源项目和纪念类网站中筛选可落地的功能，按优先级排序。
> 每条包含：功能描述 / 参考来源 / 与现有内容契合度 / 实现复杂度。

---

## 一、现状缺口速览

当前已有：落地页、领养向导（照片+抠图+性格）、陪伴（5 场景桌宠 + 抛投/视线/道具 + 亲密度）、回忆时间轴（7 类自动事件）、一封信（模板 + 60s 冷却）、心情（呼吸引导）、思念信箱（点灯）、时光胶囊、我的（分享/私密/导出 JSON/删除）。

对照纪念产品的「充实度」标准，主要有 7 个缺口：

1. **没有相册**——全程只有领养那一张图，回忆页没有照片流。
2. **分享页只读**——访客只能看，不能留言/献花/点灯，缺仪式感与「被记住」的反馈。
3. **一封信是模板**——不个性化，也没有 AI 生成。
4. **时间轴没内容可编辑**——只有系统自动事件，缺主人主动写的「生平故事/里程碑」。
5. **导出单调**——只有 JSON，没有精美的 A4 纪念手册/PDF。
6. **单人使用**——无家庭协作。
7. **数据躺在库里**——陪伴统计、亲密度没被可视化，页面对比「空」。

## 三、候选功能清单（按优先级排序）

### P0 —— 直接补「薄」，契合度高，建议优先

#### 1. 纪念相册 / 照片墙（多图上传 + 瀑布流/时间轴）

- **功能描述**：领养只留一张图。新增「相册」模块，支持批量上传多张照片（可配一句备注、可选日期），按时间分组，展示为瀑布流或时间轴卡片，照片也可进入回忆时间轴成为 `photo` 事件。
- **参考来源**：RainbowPetAI（每馆 5–100 张照片）、念念追思（照片相簿）、宠物数字星球（相册时间线）、Light a Paw（照片墙）。
- **契合度**：极高——已有 `photo` 事件类型、图片压缩/抠图管线，缺的只是存储与展示层。
- **复杂度**：中（新增 `photo` 表 + 上传接口 + 相册页；后端 MyBatis-Plus 顺手，前端复用已有压缩逻辑）。

#### 2. 访客留言 + 献花/点灯（分享页互动化）

- **功能描述**：分享页 `/s/{code}` 现在只读。让访客能留言、点亮蜡烛、献花（可匿名），主人可设置「留言需审核后显示」。这是纪念产品最核心的仪式感与「被记住」反馈。
- **参考来源**：Light a Paw（点烛/献花/留言）、念念追思（留言/点灯献花/审核）、RainbowPetAI（留言待审核）、灵堂网（留言墙）。
- **契合度**：极高——已有 share 页与 `TributePublic` 结构，扩展为双向即可。
- **复杂度**：中（新增访客身份 + `visitor_tribute` 表 + 审核态；需与现有私密开关联动）。

#### 3. 真·AI 写信 / 告别信（个性化一封信）

- **功能描述**：「一封信」目前是模板。接入 LLM，基于宠物的名字/性格/陪伴天数/主人写下的回忆，生成一封真正贴合的信，支持流式输出与「再写一封」。文案边界继续坚持「不是复活，只是替你收好没说完的话」。
- **参考来源**：宠物数字星球（AI 疗愈对话、告别信）、AI-tamago（LLM 驱动宠物 thoughts/feelings）。
- **契合度**：高——已有 letter 页 + 60s 冷却 + 模板 + 后端，缺 LLM 接入与 prompt 边界控制。
- **复杂度**：中（后端接云大模型或本地 Ollama；重点在 prompt 边界，避免越界承诺「它回来了」）。

#### 4. 生平故事 / 里程碑编辑器（让时间轴有内容）

- **功能描述**：时间轴目前只有系统自动事件。新增「里程碑」编辑：主人主动补写相遇、生日、趣事、离开等节点，可配图、配日期，形成真正的生命历程。
- **参考来源**：念念追思（生命历程时间轴）、灵堂网（生平事迹/重要时刻）、RainbowPetAI（生平故事）。
- **契合度**：高——已有 `milestone` 事件类型与时间轴 UI，缺的只是编辑入口。
- **复杂度**：低（复用 event 表 + 一个编辑表单，是最快的「补内容」手段）。

### P1 —— 增强互动与仪式感

#### 5. 存在强度分档 + 一键暂停/隐藏（陪伴页克制模式）

- **功能描述**：把陪伴页桌宠互动做成三档——**静静留影**（静态）/ **轻微陪伴**（呼吸感、偶尔眨眼）/ **熟悉互动**（点击/拖拽/抛投/道具全开），并支持一键暂停所有动画。呼应「安静而非黏人」。
- **参考来源**：留光花园（三档存在强度、一键暂停、减少动态）。
- **契合度**：极高——直接映射到现有桌宠状态机，是产品哲学层面的补强。
- **复杂度**：低（前端加档位开关 gate 动作/道具，可落盘到 pet 偏好）。

#### 6. 纪念日 / 往年今日（周年与「回看往年今日」）

- **功能描述**：落地页文案承诺了「回看往年今日」但未实现。按 `sinceDate` 计算陪伴天数/周年，生日/相遇日/忌日当天在陪伴页和时间轴给温柔提醒，并支持「往年今日」回看往年同日的记录。
- **参考来源**：灵堂网（生日忌日祭扫）、念念追思（纪念日）。
- **契合度**：极高——文案已埋点，`days` 已在后端计算。
- **复杂度**：低（纯前端日期计算 + 可选后端纪念日配置）。

#### 7. 陪伴数据可视化 / 月度回顾

- **功能描述**：把 touch/feed/play 统计做成可视化：陪伴天数、互动热力图、亲密度曲线、月度回顾卡片（本月摸了它几次、写了信没有），让「我的/陪伴」页有内容感。
- **参考来源**：念念追思（访客分析仪表板）、Forest 等养成类 app 的统计页。
- **契合度**：中高——已有 stats 与 intimacy 派生，缺展示层。
- **复杂度**：中低（前端轻量手绘 SVG 图表 + 一个聚合接口，不必引重图表库）。

#### 8. 纪念植物 / 花园养成（照料一株植物）

- **功能描述**：陪伴页场景里种一株可照料的植物（浇水/日照），随互动和天数成长，作为「花园」隐喻的低频陪伴行为。
- **参考来源**：留光花园（照料一株植物、微缩庭院）、灵堂网（栽种纪念树）。
- **契合度**：高——陪伴页已有 5 场景 CSS 绘制，加植物层很自然。
- **复杂度**：中（植物状态机 + 若干 CSS 形态，可先做单株）。

### P2 —— 锦上添花 / 长期方向

#### 9. A4 纪念手册 / 精美 PDF 导出

- **功能描述**：一键把照片、时间轴、信、留言精选排版成可打印的 A4 纪念手册（PDF），替代现在单调的 JSON 导出。
- **参考来源**：念念追思（自动生成 A4 纪念手册）、灵堂网（电子纪念册）。
- **契合度**：中——已有导出 JSON，升级为排版导出。
- **复杂度**：中高（服务端排版/PDF 生成，或前端打印样式 + 浏览器打印）。

#### 10. 家庭协作 / 多成员共同维护

- **功能描述**：邀请家人共同上传照片、写回忆、管理空间（协作者模型）。
- **参考来源**：念念追思（协作者）、灵堂网（协作维护）。
- **契合度**：中——当前是单 `nn_uid` 匿名模型，需引入账号/邀请机制。
- **复杂度**：高（权限模型 + 邀请码 + 账号体系，与匿名身份有冲突需设计）。

#### 11. 背景音乐 / 环境声（可选、默认静音）

- **功能描述**：纪念页/陪伴页可选的柔和环境音，或主人上传的宠物生前声音片段；默认关闭、可静音。
- **参考来源**：灵堂网（播放音乐）、留光花园（默认静音原则）。
- **契合度**：中——增强氛围，但要注意克制。
- **复杂度**：低（音频资源 + 开关，注意浏览器 autoplay 限制）。

#### 12. 多宠物支持

- **功能描述**：一个空间养多只宠物，切换查看。
- **参考来源**：RainbowPetAI（多纪念馆）、念念追思（宠物天堂多主题）。
- **契合度**：中——当前数据模型是单宠物（`nn_uid` → pet）。
- **复杂度**：高（数据模型改造，牵一发动全身）。

#### 13. 桌面宠物 Electron 版

- **功能描述**：把桌宠做成常驻桌面的 Electron 应用。
- **参考来源**：BongoCat（24.6k★ 交互桌宠）、宠物数字星球（桌面宠物）。
- **契合度**：中——复用前端组件，但属新平台。
- **复杂度**：高（新平台 + 常驻 + 数据同步）。

#### 14. 节日 / 节气氛围彩蛋

- **功能描述**：清明、冬至、宠物生日等节点，陪伴页场景换主题、时间轴给一张小卡片。
- **参考来源**：灵堂网（清明专题）、留光花园（低频环境变化）。
- **契合度**：中。
- **复杂度**：低。

## 四、优先级总览与落地建议

| 优先级 | 功能 | 复杂度 | 一句话理由 |
|---|---|---|---|
| P0 | 4 里程碑编辑器 | 低 | 最快的「补内容」手段 |
| P0 | 6 往年今日 | 低 | 文案已埋点，纯前端 |
| P0 | 1 相册/照片墙 | 中 | 内容单薄的直接解药 |
| P0 | 2 访客留言/献花 | 中 | 纪念产品的仪式感核心 |
| P0 | 3 AI 写信 | 中 | 把模板信变真，价值感强 |
| P1 | 5 存在强度分档 | 低 | 产品哲学补强，改动小 |
| P1 | 7 数据可视化 | 中低 | 让已有数据「可见」 |
| P1 | 8 纪念植物 | 中 | 花园隐喻，低成本 |
| P2 | 9 A4 手册 / 11 音乐 / 14 节日 | 低–中高 | 锦上添花 |
| P2 | 10 家庭协作 / 12 多宠物 / 13 桌宠端 | 高 | 长期方向，需动数据模型 |

**建议的推进顺序（两批）**

- **第一批（快速补薄，1–2 天）**：里程碑编辑器 → 往年今日 → 相册。三者都是「把页面的内容量撑起来」，改动集中在新增/复用现有表与前端展示，风险低、演示效果立竿见影。
- **第二批（提价值，1 周内）**：访客留言/献花 → AI 写信 → 存在强度分档。前两者让「被记住」与「真话」落地，后者是低成本的产品哲学补强。
- **长期**：家庭协作、多宠物、桌宠端需要在数据模型/账号体系上做一次升级，建议单独立项，不与比赛演示节奏强耦合。

**一处特别提醒**：留光花园这份 PRD 在伦理边界上非常值得我们对齐——「不主动推断离世、不做负罪提醒（连续签到/别忘了我）、不做数字复活叙事、默认静音、一键暂停、导出/删除不被付费锁住」。我们的 AI 写信与访客互动如果要做，也应延续「安静、克制、可退出」的基调，而不是做成黏性签到产品。
